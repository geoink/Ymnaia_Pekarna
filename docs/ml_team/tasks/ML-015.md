# ML-015. Провести наблюдение без изменения производства

**Приоритет:** P0 · **Роль:** аналитик + управляющий · **Поставка:** R3

**Оценка:** 3 человеко-дн. активной работы. Ожидание данных и наблюдение считаются отдельно.

**Статус:** proposed — постановка подготовлена; исполнитель и календарная дата ещё не назначены.

**Зависимости:** ML-005, ML-011, ML-012, ML-013, ML-014.

## Цель

Проверить работу системы в ежедневном процессе до влияния на выпуск.

## Входы

Общая постановка: `docs/ml_team/brief.md`; результаты прототипа: `reports/results.md` и `reports/research/results.md`. Артефакты зависимых задач должны быть приняты до начала работ. Для задач внедрения нужны данные пилотной пекарни; открытый исторический набор их не заменяет.

## Работы

1. Минимум 14 рабочих дней сохранять прогноз и ручной план до фактических продаж.
2. Собирать качество входов, своевременность расчёта, overrides, выпуск, остатки и обратную связь.
3. Разобрать нарушения и сформировать go/no-go для контролируемого пилота.

## Результат поставки

- `reports/shadow_report.md`
- `reports/shadow_daily.csv`
- `shadow_gate.md`

## Критерии приёмки

- [ ] Все 14 рабочих дней имеют заранее сохранённый прогноз или явный журнал сбоя.
- [ ] Предварительная цель своевременности ≥95%; недостающие критичные данные блокируют переход.
- [ ] Решение о запуске пилота подписано владельцем процесса и ML Lead.
- [ ] В отчёте нет причинного вывода о снижении списаний, поскольку выпуск не меняли.

## Порядок сдачи

PR с артефактами и свидетельствами проверок; ревью владельца роли по плану поставки. Имена файлов выше — ожидаемые будущие результаты задачи, а не утверждение об их наличии. При отсутствии входов указать блокер и владельца; не заменять фактические данные вымышленными.
