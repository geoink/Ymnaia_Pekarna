# ML-016. Спроектировать контролируемый пилот и рассчитать объём

**Приоритет:** P0 · **Роль:** аналитик + ML Lead · **Поставка:** R4

**Оценка:** 3 человеко-дн. активной работы. Ожидание данных и наблюдение считаются отдельно.

**Статус:** proposed — постановка подготовлена; исполнитель и календарная дата ещё не назначены.

**Зависимости:** ML-001, ML-005, ML-007.

## Цель

Определить способ измерить реальную бизнес-пользу без выбора удобных метрик после опыта.

## Входы

Общая постановка: `docs/ml_team/brief.md`; результаты прототипа: `reports/results.md` и `reports/research/results.md`. Артефакты зависимых задач должны быть приняты до начала работ. Для задач внедрения нужны данные пилотной пекарни; открытый исторический набор их не заменяет.

## Работы

1. Выбрать единицу рандомизации: store-week при нескольких точках или switchback по блокам для одной пекарни.
2. Учесть общую печь, замещение SKU, дни недели, перенос остатков, тренд и carryover.
3. На предэкспериментальных данных оценить дисперсию, мощность, MDE, длительность и план анализа.
4. Заранее определить основную денежную метрику, guardrails доступности, остановку и обращение с overrides.

## Результат поставки

- `pilot_protocol.md`
- `power_analysis.ipynb`
- `randomization_schedule.csv`

## Критерии приёмки

- [ ] Гипотеза, единица анализа, primary metric, MDE и правила исключения подписаны до начала.
- [ ] Длительность рассчитана, а не автоматически установлена в две недели.
- [ ] Зависимость наблюдений внутри магазина/временного блока учтена.
- [ ] План и seed рандомизации сохранены; нет анализа эффекта по искусственным 8 независимым SKU.

## Порядок сдачи

PR с артефактами и свидетельствами проверок; ревью владельца роли по плану поставки. Имена файлов выше — ожидаемые будущие результаты задачи, а не утверждение об их наличии. При отсутствии входов указать блокер и владельца; не заменять фактические данные вымышленными.
