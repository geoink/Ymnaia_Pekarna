# ML-008. Сравнить сильные простые методы и бустинг

**Приоритет:** P1 · **Роль:** Data Scientist · **Поставка:** R2

**Оценка:** 3 человеко-дн. активной работы. Ожидание данных и наблюдение считаются отдельно.

**Статус:** proposed — постановка подготовлена; исполнитель и календарная дата ещё не назначены.

**Зависимости:** ML-006, ML-007.

## Цель

Проверить, оправдана ли сложность ML относительно лучшего доступного простого правила.

## Входы

Общая постановка: `docs/ml_team/brief.md`; результаты прототипа: `reports/results.md` и `reports/research/results.md`. Артефакты зависимых задач должны быть приняты до начала работ. Для задач внедрения нужны данные пилотной пекарни; открытый исторический набор их не заменяет.

## Работы

1. Добавить ETS с недельной сезонностью и явно описанной обработкой неизвестных дней.
2. Сравнить lag7, среднее/медиану одинаковых дней недели, скользящее среднее, HGB MAE и Poisson.
3. Ограничить подбор параметров внутренними временными окнами; показать вклад групп признаков.

## Результат поставки

- `configs/candidates_v2.json`
- `reports/benchmark_v2.csv`
- `reports/selection_v2.json`

## Критерии приёмки

- [ ] Все кандидаты получают одинаковые доступные данные и одинаковый горизонт.
- [ ] Показаны WAPE, MAE, MASE7, RMSSE7, bias по SKU и окнам, худшие сегменты и стоимость расчёта.
- [ ] Основной кандидат выбран без обращения к новому тесту; ухудшения не скрыты.
- [ ] Poisson не объявлен победителем только на основании старого теста.

## Порядок сдачи

PR с артефактами и свидетельствами проверок; ревью владельца роли по плану поставки. Имена файлов выше — ожидаемые будущие результаты задачи, а не утверждение об их наличии. При отсутствии входов указать блокер и владельца; не заменять фактические данные вымышленными.
