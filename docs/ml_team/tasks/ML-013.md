# ML-013. Настроить ежедневный расчёт и версионирование модели

**Приоритет:** P1 · **Роль:** ML Engineer · **Поставка:** R3

**Оценка:** 3 человеко-дн. активной работы. Ожидание данных и наблюдение считаются отдельно.

**Статус:** proposed — постановка подготовлена; исполнитель и календарная дата ещё не назначены.

**Зависимости:** ML-006, ML-008.

## Цель

Получать воспроизводимый прогноз до согласованного срока каждый рабочий день.

## Входы

Общая постановка: `docs/ml_team/brief.md`; результаты прототипа: `reports/results.md` и `reports/research/results.md`. Артефакты зависимых задач должны быть приняты до начала работ. Для задач внедрения нужны данные пилотной пекарни; открытый исторический набор их не заменяет.

## Работы

1. Упаковать загрузку, признаки, прогноз и экспорт в идемпотентный batch job.
2. Хранить версии кода, данных, признаков, модели и trained_through; настроить расписание.
3. Добавить smoke-check, повтор запуска и возврат к предыдущей версии; не загружать чужие joblib.

## Результат поставки

- `deployment/`
- `model_registry.json`
- `runbook.md`

## Критерии приёмки

- [ ] Повтор запуска на ту же дату не создаёт конфликтующих планов.
- [ ] Свежая установка воспроизводит результат на фиксированном входе.
- [ ] Лог содержит model_version, cutoff, row counts, duration и статус.
- [ ] Успешно продемонстрирован rollback к предыдущей версии.

## Порядок сдачи

PR с артефактами и свидетельствами проверок; ревью владельца роли по плану поставки. Имена файлов выше — ожидаемые будущие результаты задачи, а не утверждение об их наличии. При отсутствии входов указать блокер и владельца; не заменять фактические данные вымышленными.
