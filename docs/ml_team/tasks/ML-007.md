# ML-007. Зафиксировать протокол оценки и новый закрытый тест

**Приоритет:** P0 · **Роль:** ML Lead + Data Scientist · **Поставка:** R2

**Оценка:** 2 человеко-дн. активной работы. Ожидание данных и наблюдение считаются отдельно.

**Статус:** proposed — постановка подготовлена; исполнитель и календарная дата ещё не назначены.

**Зависимости:** ML-001, ML-004, ML-006.

## Цель

Заранее определить правила выбора новой версии модели после уже просмотренного теста 2022 года.

## Входы

Общая постановка: `docs/ml_team/brief.md`; результаты прототипа: `reports/results.md` и `reports/research/results.md`. Артефакты зависимых задач должны быть приняты до начала работ. Для задач внедрения нужны данные пилотной пекарни; открытый исторический набор их не заменяет.

## Работы

1. Воспроизвести исходный и расширенный эксперименты; сохранить версии данных и кода.
2. Определить временные окна, cutoffs, частоту обучения и список кандидатов до нового сравнения.
3. Выделить новые данные конкретной пекарни и закрыть доступ к тестовым метрикам до фиксации кандидата.

## Результат поставки

- `evaluation_protocol_v2.md`
- `splits_v2.json`
- `reports/reproducibility.md`

## Критерии приёмки

- [ ] Протокол содержит primary metric, baseline, сегменты, бюджет подбора и критерий promotion.
- [ ] MASE/RMSSE масштабируются только обучающей историей; undefined значения и их количество показаны.
- [ ] Даты и достаточная длина нового теста определены до его открытия; без свежих данных статус blocked.
- [ ] Ни август–сентябрь 2022, ни 11 ретроспективных окон не названы новым независимым тестом.

## Порядок сдачи

PR с артефактами и свидетельствами проверок; ревью владельца роли по плану поставки. Имена файлов выше — ожидаемые будущие результаты задачи, а не утверждение об их наличии. При отсутствии входов указать блокер и владельца; не заменять фактические данные вымышленными.
