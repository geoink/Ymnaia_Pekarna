# ML-005. Начать учёт выпуска, остатков, списаний и отсутствия товара

**Приоритет:** P0 · **Роль:** аналитик + управляющий + Data Engineer · **Поставка:** R1

**Оценка:** 4 человеко-дн. активной работы. Ожидание данных и наблюдение считаются отдельно.

**Статус:** proposed — постановка подготовлена; исполнитель и календарная дата ещё не назначены.

**Зависимости:** ML-001, ML-003.

## Цель

Собрать данные для оценки фактических потерь и ограничения продаж наличием.

## Входы

Общая постановка: `docs/ml_team/brief.md`; результаты прототипа: `reports/results.md` и `reports/research/results.md`. Артефакты зависимых задач должны быть приняты до начала работ. Для задач внедрения нужны данные пилотной пекарни; открытый исторический набор их не заменяет.

## Работы

1. Добавить партии выпуска, остатки открытия/закрытия, списания с причинами и интервалы stockout.
2. Различать неизвестное наличие и подтверждённый нулевой остаток; определить частоту наблюдений.
3. Сверять баланс: открытие + выпуск + поступления − продажи − списания − перемещения = закрытие с учётом возвратов.

## Результат поставки

- `schemas/inventory.schema.json`
- `inventory_collection_guide.md`
- `reports/balance_audit.md`

## Критерии приёмки

- [ ] Есть минимум 7 последовательных рабочих дней наблюдений для всех пилотных SKU.
- [ ] Не менее 95% обязательных полей заполнено; порог предварительный, утверждается в ML-001.
- [ ] Все расхождения баланса превышающие согласованный допуск разобраны.
- [ ] Время исчерпания товара фиксируется либо отмечается неизвестным; продажи не переименованы в спрос.

## Порядок сдачи

PR с артефактами и свидетельствами проверок; ревью владельца роли по плану поставки. Имена файлов выше — ожидаемые будущие результаты задачи, а не утверждение об их наличии. При отсутствии входов указать блокер и владельца; не заменять фактические данные вымышленными.
