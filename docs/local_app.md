# Проверка модели на своих продажах

В проекте есть локальное веб-приложение. Оно принимает продажи CSV или Excel, определяет ассортимент, заново обучает модель и выдаёт прогноз на следующий день после конца файла. Сохранённые результаты курсовой при этом не меняются.

## Запуск

1. Установите [Python 3.11 или новее](https://www.python.org/downloads/). На Windows при установке отметьте **Add Python to PATH**.
2. Распакуйте архив проекта в отдельную папку.
3. На macOS откройте **Запустить.command**, на Windows — **Запустить.bat**. При первом запуске установятся библиотеки, поэтому понадобится интернет. После установки расчёт работает без интернета.
4. Браузер откроет `http://127.0.0.1:8765`. Окно Терминала оставьте открытым, пока работаете с моделью. Для остановки нажмите в нём Ctrl+C.

Если macOS не разрешает открыть файл запуска, выполните в Терминале из папки проекта:

```bash
python3 run_app.py
```

В Windows та же команда выглядит как `py -3 run_app.py`. В Linux используйте `python3 run_app.py`.

Если порт занят, используйте `python3 run_app.py --port 8766`. Если браузер не открылся автоматически, скопируйте адрес из Терминала. Сам `index.html` без работающего Python-приложения прогноз не рассчитывает.

Установка создаёт папку `.app-venv` внутри проекта. При следующих запусках используется это же окружение с установленными библиотеками.

Для разработчика с активированным окружением:

```bash
python -m pip install -e '.[dev,app]'
bakery-app
```

## Сначала попробуйте пример

Нажмите **«Испытать на примере»**, затем **«Обучить и получить прогноз»**. В примере три товара за 120 дней. Это синтетические данные для проверки интерфейса, отдельно от реального датасета курсовой. Дата прогноза в примере — 29 сентября 2026 года.

Пример можно [скачать из репозитория](../src/bakery_forecast/web/demo.csv). Шаблон с несколькими строками доступен по кнопке в приложении; для обучения его нужно заполнить своей историей.

## Подготовьте файл

Нужны три столбца. Названия можно выбрать вручную после загрузки.

| Дата | Товар | Продано |
|---|---|---:|
| 2026-06-01 | Багет | 82 |
| 2026-06-01 | Круассан | 45 |
| 2026-06-02 | Багет | 79 |
| 2026-06-02 | Круассан | 0 |

- Формат: CSV в UTF-8 или Windows-1251 либо Excel `.xlsx`. В Excel читается первый лист.
- Даты: `2026-06-01` или `01.06.2026`; в Excel допустимы обычные ячейки типа «дата».
- Количество: число, десятичный разделитель — точка или запятая. Единицы всех товаров должны соответствовать штукам, если вы используете округлённый прогноз.
- В CSV допустимы запятая, точка с запятой или табуляция между столбцами.
- Ограничения: до 8 МБ, 100 000 строк, 60 столбцов, 100 товаров и пяти лет истории.

Нужна история минимум за 84 календарных дня. Первые 35 дней формируют признаки, последние 14 отводятся под проверку. У каждого выбранного товара должно остаться минимум 28 известных наблюдений в обучении и 7 в проверке. Для нового товара без достаточной истории модель пока не применяется: его можно снять с выбора.

Количество позиций определяется по названиям товаров. Используйте одинаковое написание в течение всей истории. Несколько строк с одинаковой датой и товаром суммируются, поэтому можно загрузить как дневные итоги, так и отдельные продажи. Не загружайте в одном файле одновременно итоги и составляющие их чеки: это удвоит продажи.

## Как учитываются пропуски

По умолчанию отсутствие строки по товару означает неизвестные продажи. Если вы уверены, что товар был в ассортименте и отсутствие строки означает нулевые продажи, выберите соответствующее правило.

День, в который нет записей ни по одному товару файла, всегда остаётся неизвестным. Даты до первого появления товара также остаются неизвестными. Явный ноль в файле учитывается как ноль. Отрицательные строки считаются корректировками: после суммирования отрицательный дневной итог заменяется нулём. Количество таких случаев видно под таблицей.

Приложение не знает, закончился ли товар раньше закрытия. Поэтому прогнозирует наблюдаемые продажи, а не полный неудовлетворённый спрос. Для закрытого дня или праздника решение о выпечке нужно проверить отдельно.

## Что показывает результат

- Прогноз ML на один день и округлённое число единиц по каждому выбранному товару.
- Прогноз по правилу «неделю назад» для сравнения. Если нужного прошлого дня нет, используется среднее известных продаж за 28 дней, затем среднее всей прошлой истории.
- WAPE и MAE на последних двух неделях. WAPE — сумма абсолютных ошибок, делённая на сумму продаж; MAE — средний промах в штуках на товар за день. Меньше — лучше. При нулевых суммарных продажах WAPE не определён.
- Ошибки по товарам и смещение: положительное означает завышение прогноза, отрицательное — занижение.
- История последних 56 дней, прогнозы на проверке и точка следующего дня. Неизвестные значения показаны разрывами.
- CSV с прогнозами, который можно открыть в Excel. Скачивание — единственная операция, при которой приложение предлагает сохранить результат на диск.

Проверка имитирует ежедневный прогноз: для каждого дня уже известны фактические продажи всех предыдущих дней, а веса модели в течение проверки не меняются. Это не прогноз сразу на две недели из одной даты. После проверки модель заново обучается на всей истории и рассчитывает следующий день.

Модель — `HistGradientBoostingRegressor` с абсолютной ошибкой и параметрами основной работы. В признаки входят товар, день недели, месяц, сезонные признаки, продажи 1/7/14/28 дней назад и скользящие статистики. Случайного перемешивания дат нет.

Короткая проверка может показать, что простой прогноз точнее ML. Приложение выводит фактические ошибки обоих методов. Прогноз не учитывает остатки, акции, погоду, себестоимость и мощность печи; эти сведения нужны для окончательного решения об объёме выпечки.

## Где хранятся данные

Сервер слушает только `127.0.0.1`. Продажи не отправляются на внешний сервер и не записываются в репозиторий. В памяти хранятся не более четырёх загруженных таблиц; каждая удаляется через час или при закрытии приложения. После перезапуска данные нужно загрузить ещё раз.

## Если расчёт не запускается

| Сообщение | Что проверить |
|---|---|
| Нужно 84 дня истории | Загрузите больше дат; несколько итоговых чисел по товарам недостаточно для временного прогноза. |
| Недостаточно наблюдений у товара | Добавьте продажи этого товара или исключите его из расчёта. |
| Проверьте строки… | Посмотрите указанные строки с учётом заголовка: дата, название и количество обязательны. |
| Срок хранения истёк | Повторно загрузите файл; также это возможно после загрузки более четырёх файлов. |
| Нет связи с приложением | Проверьте окно Терминала; при необходимости запустите приложение заново. |
| Не удалось установить библиотеки | Проверьте интернет и версию Python, повторите запуск. |
